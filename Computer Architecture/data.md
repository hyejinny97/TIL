# ✔ 데이터

- 컴퓨터는 0과 1로 모든 정보를 표현하고, 0과 1로 표현된 정보만을 이해할 수 있음

## 1️⃣ 0과 1로 숫자를 표현하는 방법

### 정보 단위

- 비트 (bit): 0과 1을 나타내는 가장 작은 정보 단위
  - n 비트는 2^n가지 정보를 표현할 수 있음
- 바이트 (byte): 여덟 개의 비트를 묶은 단위

| 정보 단위        | 크기                     |
| ---------------- | ------------------------ |
| 1바이트(1byte)   | 8비트 (8bit)             |
| 1킬로바이트(1KB) | 1000바이트 (1,000byte)   |
| 1메가바이트(1MB) | 1000킬로바이트 (1,000KB) |
| 1기가바이트(1GB) | 1000메가바이트 (1,000MB) |
| 1테라바이트(1TB) | 1000기가바이트 (1,000GB) |

#### cf) 워드 (word)

- CPU가 한 번에 처리할 수 있는 데이터 크기
- ex) 1워드=16비트인 경우, CPU가 한 번에 16비트 처리 가능
- 현대 컴퓨터의 워드 크기는 대부분 32비트 또는 64비트임

### 이진법

- 이진법 (binary): 0과 1만으로 모든 숫자를 표현하는 방법
  - 숫자가 1을 넘어가는 시점에 자리 올림함
  - 이진수: 이진법으로 표현한 수
- 십진법 (decimal): 0부터 9까지만으로 모든 숫자를 표현하는 방법
  - 숫자가 9를 넘어가는 시점에 자리 올림함
  - 십진수: 십진법으로 표현한 수

#### 이진수 표기 방법

1.  이진수 끝에 아래첨자 (2)를 붙임
2.  이진수 앞에 0b를 붙임

#### 이진수의 음수 표현

- 2의 보수를 구해 이진수의 음수를 표현할 수 있음
- 2의 보수
  - 사전적 정의: 어떤 수를 그보다 큰 2^n에서 뺀 값
  - 쉬운 정의: 모든 0과 1을 뒤집고, 거기에 1을 더한 값
- ex) 11(2)의 음수 = 01(2)
- 컴퓨터 내부에서 어떤 수를 다룰 때는 이 수가 양수인지 음수인지를 구분하기 위해 플래그(flag)를 사용함

##### cf) 2의 보수 표현의 한계

- 0이나 2^n 형태의 이진수에 2의 보수를 취하면 음수값을 얻을 수 없음
- ex) 0000(2)에 2의 보수를 적용한 결과: 10000(2)
- ex) 1000(2)에 2의 보수를 적용한 결과: 1000(2)

### 십육진법

- 십육진법 (hexadecimal): 0~9, A~F까지만으로 모든 숫자를 표현하는 방법
  - 숫자가 15를 넘어가는 시점에 자리 올림함
  - 십육진수: 십육진법으로 표현한 수
- 이진법은 0과 1만으로 모든 숫자를 표한하다 보니 숫자의 길이가 너무 길어진다는 단점이 있음
- 따라서, 데이터를 표현할 때 이진법 외에 십육진법도 자주 사용됨
  - 이유: 이진수를 십육진수로, 십육진수를 이진수로 변환하기 쉬움

#### 십육진수 표기 방법

1. 십육진수 끝에 아래첨자 (16)를 붙임
2. 십육진수 앞에 0x를 붙임

#### 십육진수를 이진수로 변환하기

- 십육진수 하나는 이진수 4개로 표현 가능 (2^4 = 16)

#### 이진수를 십육진수로 변환하기

- 이진수 4개는 십육진수 하나로 표현 가능

## 2️⃣ 0과 1로 문자를 표현하는 방법

### 문자 집합과 인코딩

- 문자 집합 (character set): 컴퓨터가 인식하고 표현할 수 있는 문자의 모음
- 문자 인코딩: 문자를 0과 1로 변환하는 과정
- 문자 디코딩: 0과 1로 이루어진 문자 코드를 문자로 변환하는 과정

#### 아스키 코드

- 아스키 (ASCII): 초창기 문자 집합 중 하나로, 영어 알파벳과 아라비아 숫자, 일부 특수 문자를 포함함
- 아스키 문자들은 각각 7비트로 표현되는데, 즉 총 128개(2^7)의 문자를 표현 가능
  - 8비트 중 1비트는 패리티 비트로, 오류 검출을 위해 사용되는 비트임
- 아스키 문자는 아스키 문자 집합을 통해 아스키 코드로 인코딩 됨으로서, 아스키 문자를 0과 1로 표현할 수 있음
- 코드 포인트: 문자 인코딩에서 글자에 부여된 고유한 값
- 장점
  - 매우 간단하게 인코딩됨
- 단점
  - 한글뿐만 아니라 아스키 문자 집합 외의 문자, 특수문자 표현 불가

#### EUC-KR

- 한글은 각 음절 하나하나가 초성, 중성, 종성의 조합으로 이루어짐

##### 한글 인코딩 방식

1. 완성형 인코딩 방식

   - 초성, 중성, 종성의 조합으로 이루어진 완성된 하나의 글자에 고유한 코드를 부여하는 인코딩 방식

2. 조합형 인코딩 방식

   - 초성을 위한 비트열, 중성을 위한 비트열, 종성을 위한 비트열을 할당하여 그것들의 조합으로 하나의 글자 코드를 완성하는 인코딩 방식

##### EUC-KR

- KS X 1001, KS X 1003이라는 문자 집합을 기반으로 하는 대표적인 완성형 인코딩 방식
- 초성, 중성, 종성이 모두 결합된 한글 단어에 2바이트 크기의 코드를 부여함
  - 즉, 한글은 십육진수 4자리로 표현 가능
- 총 2,350개 정도의 한글 단어를 표현할 수 있음
- 사실 이는 모든 한글 조합을 표현할 수 있을 정도로 많은 양은 아님

#### 유니코드와 UTF-8

- 언어별로 인코딩을 나라마다 해야 한다면 다국어를 지원하는 프로그램을 만들 때 각 나라 언어의 인코딩을 모두 알아야 하는 번거로움이 있음
- 따라서, 모든 언어를 아우르는 문자 집합과 통일된 표준 인코딩 방식이 있다면 언어별로 인코딩하는 수고로움을 덜 수 있음

##### 유니코드

- EUC-KR보다 훨씬 다양한 한글을 포함하며 대부분 나라의 문자, 특수문자, 화살표나 이모티콘까지도 코드로 표현할 수 있는 통일된 문자 집합
- 각 문자마다 고유한 값이 부여됨

##### UTF-8

- 아스키 코드나 EUC-KR은 글자에 부여된 값(코드 포인트)을 그대로 인코딩 값을 삼음
- 하지만, 유니코드는 글자에 부여된 값 자체를 인코딩된 값으로 삼지 않고 다양한 방법으로 인코딩함
- 유니코드 문자에 부여된 값을 인코딩하는 방식에는 UTF-8, UTF-16, UTF-32 등이 있음
- UTF-8은 1바이트부터 4바이트까지의 인코딩 결과를 만들어 냄
- UTF-8로 인코딩한 결과가 몇 바이트가 될지는 유니코드 문자에 부여된 값의 범위에 따라 결정됨
