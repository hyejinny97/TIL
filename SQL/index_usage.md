# ✔ 인덱스의 실제 사용

- 보조 인덱스는 데이터의 중복 여부에 따라 단순 보조 인덱스와 고유 보조 인덱스로 나뉨
  - 고유 인덱스: 인덱스의 값이 중복되지 않음
  - 단순 인덱스: 인덱스의 값이 중복됨
- 기본 키나 고유 키로 지정하면 값이 중복되지 않으므로 고유 인덱스가 생성됨
- 이 외의 생성된 인덱스는 단순 인덱스로 생성됨

## 1️⃣ 인덱스 생성과 제거 문법

### 인덱스 생성 문법

```
CREATE [UNIQUE] INDEX 인덱스_이름
  ON 테이블_이름 (열_이름) [ASC | DESC]
```

- Primary Key 문법을 사용하면 클러스터형 인덱스가, Unique 문법을 사용하면 보조 인덱스가 자동으로 생성됨
- 그 외에 직접 인덱스를 생성하려면 `CREATE INDEX` 문을 사용해야 함
  - `CREATE INDEX`로 생성되는 인덱스는 보조 인덱스임
- `CREATE UNIQUE INDEX`는 중복이 안 되는 고유 인덱스를 만듦
  - `UNIQUE`를 사용해서 인덱스를 만드려면 기존에 입력된 값에 중복이 있으면 안 되고, 인덱스를 생성한 후에 입력되는 데이터도 중복이 있으면 안됨
- `ASC`/`DESC`을 통해 인덱스를 오름차순/내림차순으로 만들 수 있음
  - 기본은 `ASC`이며, `DESC`으로 만들어지는 경우는 거의 없음

### 인덱스 제거 문법

```
DROP INDEX 인덱스_이름 ON 테이블_이름
```

- 주의) 기본 키, 고유 키로 자동 생성된 인덱스는 `DROP INDEX`로 제거하지 못함
  - `ALTER TABLE` 문으로 기본 키나 고유 키를 제거하면 자동으로 생성된 인덱스도 제거할 수 있음

## 2️⃣ 인덱스 생성과 제거 실습

### 인덱스 생성 실습

- `SHOW INDEX FROM 테이블_이름`: 테이블에 생성된 인덱스 정보를 보여줌
- `SHOW TABLE STATUS 테이블_이름`: 테이블에 생성된 인덱스의 크기를 보여줌

  - 'Data_length': 클러스터형 인덱스의 크기(단위: Byte)
  - 'Index_length': 보조 인덱스의 크기(단위: Byte)

- 인덱스를 생성한 후에 `ANALYZE TABLE 테이블_이름` 문을 실행해줘야 실제로 적용됨

### 인덱스 활용 실습

- 인덱스를 사용하려면 인덱스가 생성된 열 이름이 SQL 문에 있어야 함
  - WHERE 절에 열 이름이 들어 있어야 인덱스를 사용함

### 인덱스를 사용하지 않을 때

- 인덱스가 있고 WHERE 절에 열 이름이 나와도 인덱스를 사용하지 않는 경우가 있음
- 대부분의 행을 가져와야 하는 경우, 인덱스가 있더라도 MySQL이 인덱스 검색을 통해 왔다 갔다 하는 것보다 차라리 테이블을 차례대로 읽는 것이 효율적이라고 판단해 전체 테이블 검색을 하게 됨
- 또한, WHERE 문에서 열에 연산이 가해지면 인덱스를 사용하지 않음

### 인덱스 제거 실습

- 클러스터형 인덱스와 보조 인덱스가 섞여 있을 때는 보조 인덱스를 먼저 제거하는 것이 좋음
  - 이유) 클러스터형 인덱스를 먼저 제거하면, 데이터를 쓸데없이 재구성해서 시간이 더 오래 걸림

## cf) 인덱스를 효과적으로 사용하는 방법

1. 인덱스는 열 단위에 새성됨

   - 하나의 열에 하나의 인덱스를 만드는 것이 가장 일반적임

2. WHERE 절에서 사용되는 열에 인덱스를 만들어야 함

   - SELECT 문을 사용할 때, WHERE 절의 조건에 해당 열이 나와야 인덱스를 사용함

3. WHERE 절에 사용되더라도 자주 사용해야 가치가 있음
4. 데이터의 중복이 높은 열은 인덱스를 만들어도 별 효과가 없음

   - 열에 들어갈 데이터의 종류가 몇 가지 되지 않으면 인덱스는 큰 효과를 내지 못함
   - ex) 성별, 연락처 국번 등

5. 클러스터형 인덱스는 테이블당 하나만 생성할 수 있음

   - 하나밖에 지정하지 못하는 클러스터형 인덱스(기본 키)는 조회할 때 가장 많이 사용되는 열에 지정하는 것이 효과적임

6. 사용하지 않는 인덱스는 제거해야 함
