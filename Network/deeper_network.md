# ✔ 네트워크 심화

## 1️⃣ 안정성을 위한 기술

### 가용성

- 안정성: 특정 기능을 언제든 균일한 성능으로 수행할 수 있는 특성
- 가용성(availability): 컴퓨터 시스템이 특정 기능을 실제로 수행할 수 있는 시간의 비율 (안정성의 정도를 나타내는 지표)

  - 전체 사용 시간 중에서 정상적인 사용 시간
  - 업타임: 정상적인 사용 시간
  - 다운타임: 정상적인 사용이 불가능한 시간

  ```
  가용성 = 업타임 / (업타임 + 다운타임)
  ```

- 고가용성을 유지하는 것은 모든 웹 서비스에서 가장 중요한 목표임
- 일반적으로 안정적이라고 평가받는 시스템은 99.999%(파이브 나인스) 이상을 목표로 함

  | 가용성    | 1년간 다운타임 | 한 달간 다운타임 | 한 주간 다운타임 |
  | --------- | -------------- | ---------------- | ---------------- |
  | 99.999%   | 5.26분         | 26.3초           | 6.05초           |
  | 99.9999%  | 31.56초        | 2.63초           | 0.604초          |
  | 99.99999% | 3.16초         | 0.262초          | 0.0604초         |

- 가용성을 높이려면 다운타임을 낮춰야 함
- 다운타임을 낮추고 가용성을 높이기 위해서는 결함을 감내할 수 있도록 인프라를 설계하는 것이 중요함
  - 결함 감내(fault tolerance): 문제가 발생하더라도 기능할 수 있는 능력

### 이중화/다중화

#### 이중화

- 무언가를 이중으로 두는 기술
- 예비(백업)을 마련하는 방법
- 서버 컴퓨터, NIC, 스위치와 같은 물리적 장비 뿐만 아니라 DB, 웹 서버 프로그램 등도 이중화 대상임
- 단일 장애점(Single Point Of Failure, SPoF): 문제가 발생할 경우 시스템 전체가 중단될 수 있는 대상
- 가용성을 높이기 위해 SPoF를 이중화하는 것이 좋음

#### 이중화 구성

1. 액티브/스탠바이 방식
   - 한 시스템은 가동하고, 다른 시스템은 백업 용도로 대기 상태로 두는 이중화 구성 방식
2. 액티브/액티브 방식
   - 두 시스템 모두를 가동 상태로 두는 이중화 구성 방식

#### 다중화

- 무언가를 여러 개 두는 기술
- 이중화된 구성에 비해 더욱 안정적인 운영 가능

#### 티밍(teaming), 본딩(bonding)

- 여러 개의 NIC를 이중화/다중화하여 마치 더 뛰어나고 안정적인 성능을 보유한 하나의 인터페이스처럼 보이게 하는 기술
- 티밍은 주로 윈도우, 본딩은 주로 리눅그에서 사용되는 용어임

### 로드 밸런싱

- 트래픽: 주어진 시점에 특정 노드를 경유한 패킷의 양
- 과도한 트래픽은 서버의 가용성을 떨어뜨림
- 로드 밸런싱: 트래픽의 고른 분배를 위해 사용되는 기술
- 로드 밸런서: 로드 밸런싱을 수행하는 장비
  - L4 스위치, L7 스위치와 같은 네트워크 장비
  - 로드 밸런싱 기능을 제공하는 소프트웨어(ex) HAProxy, Envoy 등)을 설치하면 일반 호스트로 로드 밸런서로 사용 가능
  - 웹 서버 소프트웨어인 Nginx에도 로드 밸런싱 기능이 포함됨
- 로드 밸런서는 일반적으로 이중화/다중화된 서버와 클라이언트 사이에 위치해, 클라이언트로부터 받은 요청을 각 서버에 균등하게 분배해줌

#### cf) 서버의 상태를 체크하는 헬스 체크

- 헬스 체크: 다중화된 서버 환경에서 현재 문제가 있는 서버는 없는지, 현재 요청에 대해 올바른 응답을 할 수 있는 상태인지를 주기적으로 검사하는 것
- 헬스 체크는 주로 로드 밸런서에 의해 이루어짐
- 서버 간에 주기적으로 하트비트라는 메시지를 주고받으면서 문제 발생을 감지하는 방법도 있음

#### 로드 밸런싱 알고리즘

- 부하가 균등하게 분산되도록 부하 대상을 선택하는 방법

1. 라운드 로빈 알고리즘
   - 단순히 서버를 돌아가며 부하를 전달
2. 최소 연결 알고리즘
   - 연결이 적은 서버부터 우선적으로 부하를 전달

- 가중치 라운드 로빈 알고리즘, 가중치 최소 연결 알고리즘: 가중치가 높은 서버가 더 많이 선택되어 더 많은 부하를 받도록 하는 알고리즘
- 서버 간 성능이 다른 경우, 주로 가중치가 적용된 알고리즘이 사용됨

### cf) 포워드 프록시와 리버스 프록시

- 오리진 서버: 자원을 생성하고 클라이언트에게 권한 있는 응답을 보낼 수 있는 HTTP 서버
- 인바운드 메시지: 오리진 서버를 향하는 메시지
- 아웃바운드 메시지: 클라이언트를 향하는 메시지
- 클라이언트와 오리진 서버 사이에는 많은 중간 서버가 있을 수 있음
- 대표적인 HTTP 중간 서버로, 포워드 프록시(프록시)와 리버스 프록스(게이트웨이)가 있음

#### 프록시

- 클라이언트가 선택한 메시지 전달 대리자
- 오리진 서버보다 클라이언트와 더 가까이 위치함
- 주로 캐시 저장, 클라이언트 암호화 및 접근 제한 등의 기능을 제공함

#### 게이트웨이

- 아웃바운드 연결에 대해 오리진 서버 역할을 함
- 수신된 요청을 변환하여 다른 인바운드 서버들로 전달하는 중개자 역할
- 클라이언트보다 오리진 서버와 더 가까이 위치함
- 캐시를 저장하거나 로드 밸런서로 동작할 수 있음

## 2️⃣ 안전성을 위한 기술

- 암호화(encryption): 원문 데이터를 알아볼 수 없는 형태로 변경하는 과정
- 복호화(decryption): 암호화된 데이터를 원문 데이터로 되돌리는 과정
- 이를 통해 안전한 데이터 송수신뿐만 아니라 인증서 기반의 검증도 가능함

### 암호와 인증서

- 키(key): 무작위한 문자열
- 키와 원문 데이터에 암호화 알고리즘(수학적 연산 과정)을 거치면 암호문이 생성됨
- 암호문은 복호화를 통해 원문 메시지를 얻을 수 있음

#### 대칭 키 암호화 방식과 공개 키 암호화 방식

##### 1. 대칭 키 암호화 방식

- 암호화와 복호화에 동일한 키를 사용
- 장점
  - 적은 부하 덕분에 암호화 및 복호화를 빠르게 수행 가능
- 단점
  - 상대방에게 안전하게 키를 전달하기 어려움

##### 2. 공개 키 암호화 방식

- 비대칭 키 암호화라고도 함
- 암호화를 위한 키와 복호화를 위한 키가 다름
- 공개 키: 누구에게나 공개해도 무방한 키
- 개인 키: 유출되지 않는 키
- 공개 키만으로 개인 키를 유추할 수 없고, 반대로 개인 키만으로 공개 키를 유추할 수 없음
- 장점
  - 키를 안전하게 공유 가능
- 단점
  - 암호화 및 복호화에 시간과 부하가 상대적으로 많이 듦

##### 3. 대칭 키 암호화 방식 + 공개 키 암호화 방식

- 각 방식의 장단점을 고려해 대칭 키 암호화 방식과 공개 키 암호화 방식을 함께 사용하는 경우가 많음
- 대칭 키를 상대에게 안전하게 전달하기 위해 공개 키로 대칭 키를 암호화하고, 개인 키로 암호화된 대칭 키를 복호화할 수 있음
- 이를 통해 대칭 키를 안전하게 공유함과 동시에 공유한 대칭 키를 이용해 빠르게 암호화/복호화를 수행할 수 있음

#### 인증서와 디지털 서명

##### 인증서

- 공개 키 인증서(public key certificate): 공개 키와 공개 키의 유효성을 입증하기 위한 전자 문서
- 인증서에는 공개 키 뿐만 아니라 누가 생성했는지, 조작되지는 않았는지, 유효 기간은 언제까지인지 등의 내용이 포함됨
- 인증 기관(Certification Authority): 인증서의 발급, 검증, 저장과 같은 역할을 수행하는 공인 기관
  - ex) IdenTrust, DigiCert, GlobalSign 등

##### 디지털 서명

- 서명 값(signature): 보증 정보로, CA가 발급한 인증서에 포함됨
- 클라이언트는 이 서명 값을 바탕으로 인증서를 검증할 수 있음
- (CA에서) 서명 값이 만들어지는 과정
  1. 인증서 내용을 해시 함수에 적용해 해시 값을 얻어냄
  2. 해시 값을 CA의 개인 키로 암호화
- (클라이언트가) 서명 값을 사용해 인증서를 검증하는 과정
  1. 서명 값을 CA의 공개 키로 복호화해 인증서 내용에 대한 해시 값을 얻음
  2. 인증서 내용을 해시 함수에 적용해 해시 값을 직접 얻어냄
  3. 직접 계산한 해시 값과 복호화해 얻은 해시 값을 비교함
  4. 두 값이 일치하다면 전달받은 인증서는 신뢰할 수 있음 (따라서, 안심하고 공개 키 사용 가능)
- 디지털 서명: 개인 키로 암호화된 메시지를 공개 키로 복호화함으로써 신원을 증명하는 절차

##### cf) 해시 값

- 해시 함수를 적용시킨 결과값
- 해시 함수: 임의의 길이의 데이터를 고정된 길이의 데이터로 변환해주는 함수
  - ex) MD5, SHA-1, SHA-2(SHA-256, SHA-384, SHA-512) 등
- 입력 데이터가 조금만 달라져도 완전히 다른 결과가 나옴
- 따라서, 해시 함수는 입력값의 변화에 매우 민감하므로 결과값인 해시 값은 주로 데이터 변조 여부를 검사하는데 사용됨

### HTTPS: SSL과 TLS

- 인증과 암호화를 수행하는 프로토콜
- TLS: SSL을 계승한 프로토콜
- HTTPS: SSL/TLS를 사용하는 프로토콜로, HTTP 메시지의 안전한 송수신을 위해 개발됨

#### HTTPS 동작 과정(TLS 1.3 기반)

1. TCP 쓰리 웨이 핸드셰이크

   - TCP 연결 수립

2. TLS 핸드셰이크

   - 암호화 통신을 위한 키 교환
   - 인증서 송수신과 검증

3. 암호화된 메시지 송수신

#### TLS 핸드셰이크

1. 클라이언트는 서버에게 ClientHello 메시지를 보냄

   - ClientHello 메시지: 암호화된 통신을 위해 서로 맞춰 봐야 할 정보들을 제시하는 메시지
   - 지원되는 TLS 버전, 사용 가능한 암호화 방식과 해시 함수, 키를 만들기 위해 사용할 클라이언트의 난수 등이 포함
   - 암호 스위트: 사용 가능한 암호화 방식과 해시 함수를 담은 정보
     - ex) TLS_AES_128_GCM_SHA256

2. 서버는 클라이언트에게 ServerHello, Certificate, CertificateVerify 메시지를 보냄

   - ServerHello 메시지: 제시된 정보를 선택하는 메시지
   - 선택된 TLS 버전, 사용 가능한 암호화 방식과 해시 함수, 키를 만들기 위해 사용할 클라이언트의 난수 등이 포함
   - Certificate 메시지: 인증서
   - CertificateVerify 메시지: 검증을 위한 디지털 서명

## 3️⃣ 무선 네트워크

### 전파와 주파수

- 전파: 약 3kHz ~ 3THz 사이의 진동수를 갖는 전자기파로, 무선 네트워크의 연결 매체임
- 통신에서 사용되는 전파에는 주파수 대역이 미리 정해져 있어, 이를 통해 서로 다른 전파 신호를 구분함

### 와이파이와 802.11

#### IEEE 802.11

- 오늘날 LAN 환경에서의 무선 통신 표준 규격
- 802.11b, 802.11g처럼 알바펫으로 다양한 규격을 표현함
- 대부분 2.4GHz, 5GHz 대역을 사용함
- IEEE 802.11 버전에 따라 사용되는 주파수, 전송 속도, 대역폭, 전송 가능한 거리, 변조 방식 등 많은 것이 달라짐

  | 표준 규격     | 주파수 대역 | 전송 속도 |
  | ------------- | ----------- | --------- |
  | IEEE 802.11a  | 5GHz        | 54Mbps    |
  | IEEE 802.11g  | 2.4GHz      | 54Mbps    |
  | IEEE 802.11n  | 2.4/5GHz    | 450Mbps   |
  | IEEE 802.11ac | 5GHz        | 6.9Gbps   |
  | IEEE 802.11ax | 2.4/5/6GHz  | 9.6Gbps   |
  | IEEE 802.11be | 2.5/56GHz   | 46.1Gbps  |

#### 와이파이

- IEEE 802.11 표준을 따르는 무선 LAN 기술

  | 세대 이름 | 표준 규격     |
  | --------- | ------------- |
  | Wi-Fi 7   | IEEE 802.11be |
  | Wi-Fi 6   | IEEE 802.11ax |
  | Wi-Fi 5   | IEEE 802.11ac |
  | Wi-Fi 4   | IEEE 802.11n  |

- 일종의 인증 마크 역할을 함
  - 특정 제품에 특정 와이파이 인증 마크가 붙어 있을 경우, 어떤 표준 규격을 지켰고 다른 제품과의 호환성 여부를 알 수 있기 때문

#### 채널

- 같은 주파수 대역(2.4GHz 또는 5GHz)을 사용하는 네트워크라 할지라도 별개의 무선 네트워크들이 존재할 수 있음
- 2.4GHz, 5GHz 주파수 대역은 채널이라 불리는 하위 주파수 대역으로 또 한번 세분화되고, 해당 채널 대역에서 통신이 이루어짐

### AP와 서비스 셋

#### AP

- Access Point
- 무선 통신 기기들을 연결하여 무선 네트워크를 구성하는 장치
- 가정에서 무선 공유기가 AP 역할을 수행함
- 일반적으로 AP에는 유선 연결 매체를 연결할 수 있는 지점이 함께 제공되어 유선 네트워크와 무선 네트워크의 연결을 담당하는 역할도 수행함
- 인프라스트럭쳐 모드: AP를 경유하여 통신이 이루어지는 무선 네트워크 통신 방식

#### 서비스 셋

- 무선 네트워크를 이루는 AP와 여러 장치들의 집합
- 서비스 셋 식별자(SSID): 무선 네트워크를 구분짓는 수단이자 무선 네트워크를 지칭하는 고유한 이름
- 와이파이의 이름이 바로 SSID임
- AP는 불특정 다수 모두에게 자신을 알리는 브로드캐스트 메시지(비컨 프레임)를 주기적으로 전송함
- 비컨 프레임 안에는 SSID와 AP의 MAC 주소 등이 포함되어 있음
